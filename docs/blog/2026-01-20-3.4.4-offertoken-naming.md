# v3.4.4 Release Notes

This release adds support for one-time purchase discount offers on Android 7.0+ and fixes field naming conventions for consistency.

## New Features

### One-Time Purchase Discount Offers (Android 7.0+)

Apply discount offers to one-time (in-app) product purchases using `offerTokenAndroid`. This feature was introduced in Google Play Billing Library 7.0 and allows you to offer discounts on consumable and non-consumable products.

```typescript
import {fetchProducts, requestPurchase} from 'expo-iap';
import type {ProductAndroid} from 'expo-iap';

// 1. Fetch products with discount offers
const products = await fetchProducts({
  skus: ['premium_upgrade'],
  type: 'in-app',
});

const product = products[0] as ProductAndroid;

// 2. Get the discount offer from discountOffers or oneTimePurchaseOfferDetailsAndroid
const discountOffer = product.discountOffers?.[0];

// 3. Purchase with the discount
if (discountOffer?.offerTokenAndroid) {
  await requestPurchase({
    request: {
      google: {
        skus: [product.id],
        // Include offerTokenAndroid for discounted purchases (Android 7.0+)
        offerTokenAndroid: discountOffer.offerTokenAndroid,
      },
    },
    type: 'in-app',
  });
}
```

### DiscountOffer Fields

When a product has discount offers, you can access these fields from `discountOffers`:

| Field | Type | Description |
|-------|------|-------------|
| `id` | `string` | Offer identifier |
| `displayPrice` | `string` | Formatted discounted price (e.g., "$4.99") |
| `price` | `number` | Numeric discounted price |
| `offerTokenAndroid` | `string` | Token to pass to `requestPurchase` |
| `percentageDiscountAndroid` | `number` | Discount percentage (e.g., 50 for 50% off) |
| `fullPriceMicrosAndroid` | `string` | Original price in micro-units |

## Breaking Changes

### Field Naming Convention Fix

The following fields have been renamed to follow the Android suffix naming convention:

| Old Name | New Name |
|----------|----------|
| `offerToken` | `offerTokenAndroid` |
| `isOfferPersonalized` | `isOfferPersonalizedAndroid` |
| `developerBillingOption` | `developerBillingOptionAndroid` |

**Why this change?**

All Android-specific fields in `RequestPurchaseAndroidProps` and `RequestSubscriptionAndroidProps` must use the `Android` suffix to clearly indicate they are platform-specific. This is consistent with other fields like `obfuscatedAccountIdAndroid` and `obfuscatedProfileIdAndroid`.

**Migration:**

```typescript
// Before (v3.4.3)
await requestPurchase({
  request: {
    google: {
      skus: ['product_id'],
      offerToken: 'discount_token',        // ❌ Old name
      isOfferPersonalized: true,           // ❌ Old name
    },
  },
  type: 'in-app',
});

// After (v3.4.4)
await requestPurchase({
  request: {
    google: {
      skus: ['product_id'],
      offerTokenAndroid: 'discount_token', // ✓ New name
      isOfferPersonalizedAndroid: true,    // ✓ New name
    },
  },
  type: 'in-app',
});
```

**Note:** The native layer supports both old and new names for backward compatibility, but TypeScript types now require the new names.

## Updated Types

- `RequestPurchaseAndroidProps.offerTokenAndroid` - Offer token for one-time purchase discounts
- `RequestPurchaseAndroidProps.isOfferPersonalizedAndroid` - Personalized offer flag (EU compliance)
- `RequestSubscriptionAndroidProps.isOfferPersonalizedAndroid` - Personalized offer flag
